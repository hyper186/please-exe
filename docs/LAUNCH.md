# Launch plan

## Positioning

**Please.exe — a tiny HR department for your very expensive autocomplete.**

The joke earns attention. Clear feedback earns repeat use. Show direct criticism staying green alongside an insult getting a specific, useful edit. Never sell fear of an account ban, claim AI has hurt feelings, or imply that flattery improves accuracy.

## First public beta

- Share a 15-second screen recording: “You’re a useless idiot” → red → targeted edit → green. Use invented text.
- Link to the free playground first; it works before installation and shows exactly what the product does.
- Offer the small ZIP, readable source, clear privacy policy and honest beta limitations.
- Use the built-in fixed-text share card: “I was put on a performance improvement plan by my prompt.” Never share real drafts automatically.
- Invite people to submit **synthetic** false positives and missed examples through GitHub issues.

Suggested launch copy: “I built a tone meter for people who argue with ChatGPT. It runs locally, tolerates blunt feedback, and occasionally tells your keyboard to take a minute. Try Please.exe.”

## Before a broad launch

1. Install on signed-in Claude and ChatGPT; verify new/existing chats, long drafts, streaming, navigation, dark mode, keyboard access and no Send interference.
2. Run the real Jev fixed sample with a server-side key; record latency, cost and disagreement examples without saving private text.
3. Build a diverse human-rated evaluation set before claiming accuracy. Include concise prompts, non-native English, dialect, quotes, code, sarcasm and task-specific frustration. Report precision/recall and error examples; don't invent a percentage from unit tests.
4. Have 10–20 willing testers use it for a week. Ask whether the nudges help or annoy them; remove noisy rules.
5. Prepare Chrome Web Store screenshots, permission explanations, privacy disclosure and support information. Publication requires the owner's developer account and any applicable store fee/review.
6. Submit to relevant communities under their rules. Product Hunt and a short creator demo are options, not a guarantee of virality. No unsolicited automated messages.

## Keep it useful

Prefer fewer, better nudges to a constantly scolding meter. Measure quality through opt-in feedback and synthetic issue examples; do not add prompt logging to obtain metrics. Keep the core free. Consider paid convenience only after users ask for it, such as managed optional checks with transparent quotas. Add Gemini after the two initial adapters pass real-world tests.

No promotion or social posting has been performed as part of building this release.
